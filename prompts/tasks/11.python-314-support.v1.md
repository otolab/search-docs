# Issue #11: Python 3.14 対応

## 作業計画

1. PyTorch 2.10 の正式発表と配布 wheel を確認し、Python 3.14 で torch.compile と指定の ModernBERT import を検証する。
2. 現在の依存関係と実行経路を調べ、Python 3.14 における解決・動作を確認する。
3. 前提を満たせば Python バージョン制限を解除し、changeset と必要なドキュメントを更新する。
4. Python 3.14 でテストし、結果と未検証事項を Issue に記録して conductor に報告する。PR 作成前に報告し、マージは行わない。

## 懸念

- Issue 作成時と異なり、db-engine は ONNX Runtime を依存し、PyTorch を直接依存していない。指定の検証は別途 PyTorch を用意する必要がある。
- 固定依存パッケージの Python 3.14 wheel 対応や、利用可能な環境・ネットワークに左右される。

## 調査経過

- PyTorch 2.10 正式リリースノートで Python 3.14 の torch.compile 対応を確認。
- macOS arm64、Python 3.14.5、PyPI の torch 2.10.0 wheel で torch.compile の演算と ModernBertModel import に成功。
- db-engine の固定依存を Python 3.14 でインストールし、Python テスト 54 件成功（ローカル socket が必要なためサンドボックス外で実行）。
- 公開される torch ランタイムは sentence-transformers を import するが、現行依存に含まれない。既存のスコープ外問題をどう扱うか conductor の判断待ち。実モデル・他 OS は未検証。

## 追加指示への調査

- GitHub main と worktree は d986177 で一致。ホームディレクトリに置くのは PID・ログで、Python 環境の明示配置はコード上見つからない。外部の環境変数は未確認。

- optional dependency として torch 選択時に導入する案があるが、Docker を含む配布方式・ロック管理・ホーム配置の前提について conductor に判断を求める。

## 追加調査と提案

- torch は CLI と builtin 設定で公開中。現行依存に sentence-transformers がなく、Python 3.14 の分離環境で RuriEmbedding.load() が import エラーを返すことを再現。
- 候補 sentence-transformers 5.1.2、torch 2.10.0、現行 transformers / huggingface-hub / numpy の Python 3.14 依存解決は dry-run で成功。実インストール・推論は未検証。
- ONNX 既定を保つ optional dependency と、torch 起動時の extra 選択を提案。Docker の提供方式、lock の追跡・配布、切り替えや並行実行時の uv 同期を含め conductor の方針判断待ち。

## 実装・検証途中の判断待ち

- torch extra、CLI / サーバでの extra 選択、Docker opt-in ビルド、ドキュメント、changeset、Python 上限解除を作業中。
- Python 3.14 の CLI で ONNX / torch 実モデルを起動し、各 256 次元 API 応答を確認。サーバ側 EmbeddingServerProcess を空きポートで builtin torch として起動し同様に確認。一時プロジェクトの検索は既存の共有 ONNX サーバ経由で成功。
- 共有サーバ自動検出は選択 runtime を照合しない。利用中の共有サーバを変更せず、期待動作を conductor に確認する。検索サーバの実験では torch 設定を誤ってトップレベルに置いていたので、torch 指定時の再利用を実験で確認したわけではない。
- torch 停止時 resource_tracker に semaphore cleanup 警告。Docker ビルドは Linux NVIDIA 依存取得中に判断待ちのため中断し未検証。

## 共有サーバと独立検証

- runtime はローカル起動の選択として使用され、共有サーバの自動検出が優先。builtin runtime=torch を指定した実験でも既存の共有 ONNX サーバが採用された。利用中プロセスは変更していない。
- 既存の共有優先契約を維持し、利用者向けにローカル起動時の選択であることを説明する案を Issue に記録。判定ロジックの変更はしていない。
- Python 3.14 関連テスト 87 件成功。torch サーバ単体への SIGTERM でも semaphore cleanup 警告を再現。モデル推論後の通常終了では警告なし。原因・長期影響は未確認。
- Docker ビルドは Linux の NVIDIA 関連依存の取得に時間を要しており、検証を継続中。
- 標準 Docker のビルドと ONNX 実モデルの API 動作は成功。torch Docker は多数の NVIDIA 依存を長時間取得し、検証中に空き容量が約 72 GiB から 57 GiB に減ったため中断。変化の原因を本ビルドのみに帰属できない。cache は削除していない。CPU wheel の index 選択は配布方針に影響するため conductor 判断待ち。
- サーバ側の共有優先回帰テストを追加し、関連テスト 12 件成功。SIGINT では torch サーバが終了コード 0 で警告なし、SIGTERM では warning が再現。
