## 作業計画

- Issue の観測を仮説として扱い、daemon 起動時の所有権、readiness、PID 記録、既存 stop 契約と foreground の処理を調べる。
- 隔離した状態ディレクトリと空きポートを使い、対象の PID / PPID / PGID を確認して SIGINT / SIGTERM と中断時点を可能な範囲で反復検証する。実験由来のプロセスだけを回収する。
- 必要な修正と回帰テストを行い、正常起動後の停止・復旧と利用者向け説明も確認する。検証できない OS や条件を明記する。
- 想定外の発見や方針変更が必要な場合、また PR 作成前に conductor に報告する。

## 現時点のメモ

Issue の残存観測は一度だけであり、原因や自然終了の有無は未確定。foreground はシグナル処理を持つが、daemon の readiness 待ちでは同等の処理が見当たらない。所有権が移る時点を含めて確認する。

## 調査中の論点

空きポート確認と readiness / LISTEN 所有者の取得は別々に行われる。間に別の embedding サーバが同じポートを取得した場合、その応答と PID を起動した子のものとして記録する可能性がある。コード読解上の可能性で、再現は未確認。後続の stop に影響しうるため、対応範囲を conductor に確認する。状態ディレクトリは `os.homedir()` に基づくため、実験時は HOME の隔離方法と実際の解決先を確認する。

## 検証途中

モックで空き確認後の readiness と異なる LISTEN PID を与えると、その PID が管理対象として保存されることを確認した。実 OS で競合が生じる頻度は未確認。macOS で隔離 HOME・空きポート・fake uv を使った SIGINT 実験は CLI が 5 秒以内に終了しなかった。SIGINT の継承設定を明示して再試行しても同様で、原因は未確認。実験用 CLI と確認済み専用 PGID は各回回収した。SIGTERM は未実施。

## 再検証・実装

前述の「CLI が終了しなかった」は Volta のラッパー PID を送信先とした誤認。Node 実体を直接起動して CLI PID を対象に再検証した。macOS の fake uv では SIGINT / SIGTERM とも修正前は子が残り、修正後は各 2 条件で終了した。疑似端末 Ctrl-C、別ポートの HTTP サーバへの非干渉、fake HTTP サーバの起動・停止・再起動も確認した。実 uv の offline 試験は Python 依存のキャッシュ不足により準備に至らず、実 Python と他 OS は未検証。

SIGINT / SIGTERM の捕捉、準備待ちの中止、起動したプロセスツリーの回収、PID 記録前後の競合確認を実装。ユニットテストと CLI リファレンスを更新。既存の別サーバ PID 誤登録はモックで条件を確認した独立問題として残す。PR 前に conductor へ報告する。
