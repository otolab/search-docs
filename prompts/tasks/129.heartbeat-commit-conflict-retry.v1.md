# Issue #129 LanceDB commit conflict リトライ

## 作業計画

- `packages/db-engine/src/python/worker.py` の `claim_writer` / `update_heartbeat` に、LanceDB の Retryable commit conflict を正常系の競合として扱う指数バックオフリトライを追加する。
- `packages/server/src/watcher/watcher-process.ts` の heartbeat 更新失敗時に、一時的な競合で FileWatcher を停止しないようにし、リトライ枯渇または master 喪失確認時だけ既存の sleeping 遷移を行う。
- Python の heartbeat 書き込みリトライテストと、必要な TypeScript 側の失敗系テストを追加する。
- 設計文書の heartbeat 説明を実装と照合し、影響がある場合のみ最小限更新する。
- 対象テスト・型チェック・lint を実施し、Issue と PR に受け入れ条件対応と未検証事項を記録する。

## 受け入れ条件チェックリスト

- [x] Retryable commit conflict 発生時に `update_heartbeat` / `claim_writer` が自動リトライする
- [x] 一時的な競合で WatcherProcess が FileWatcher を停止しない
- [x] リトライ枯渇時は適切にエラーログを出し、既存の failover 動作を維持する
- [x] 並行書き込みのテストが追加されている

## 調査結果

- Issue 本文・コメントで、`Retryable commit conflict` と `Please retry` を正常系の競合として指数バックオフで扱う方針が合意されている。
- 現在の `claim_writer` / `update_heartbeat` は `table.add(..., mode='overwrite')` を一度だけ実行し、例外を伝播する。
- 現在の `WatcherProcess.startHeartbeat()` は `updateHeartbeat()` の一度の失敗で `transitionToSleeping()` を実行する。
- `docs/client-server-architecture.md`、`docs/architecture.md`、`docs/state-model.md` は heartbeat 状態遷移と overwrite を説明しているが、競合リトライの記載はない。
- 作業ツリーはクリーンで、ブランチ `ensemble/issue-129` は `origin/main` 直上。
