# Issue #122: config init の既存設定非上書き

## 作業計画

1. 既存設定（推奨パスおよびレガシーパス）を置いた状態で CLI/MCP の `force: false` 動作を再現確認する。
2. `initConfig` と MCP ラッパーの成功・スキップ結果の扱いを確認し、Issue の受け入れ条件を満たす最小修正を行う。
3. CLI/MCP の回帰テストを追加し、関連テスト・型チェックを実行する。
4. 変更をコミットし、PR と Issue コメントで結果を引き継ぐ。

## 着手時点の確認

- ブランチ: `ensemble/issue-122`
- 作業ツリー: クリーン
- 共通実装: `packages/cli/src/commands/config/init.ts`
- MCP ラッパー: `packages/mcp-server/src/tools/init.ts`
- CLI の既存テストには `force: false` 相当の非上書き確認がある。
- MCP の成功レスポンスは `initConfig` の戻り値を区別していない。

## 経過メモ

- CLI の `initConfig({ cwd, force: false })` は、既存の `.search-docs/config.json` を検出して情報メッセージを出力し、ファイル内容を変更しなかった（実動作で確認）。
- `initConfig` の戻り値は `void` であり、MCP `init` はスキップと作成・上書きを区別せず、常に完了メッセージを返す実装になっている。
- 方針: `initConfig` の戻り値を `created | skipped | overwritten` とし、MCP は `skipped` 時に警告と「既存設定は変更されていない」旨を返す。設定が実際に作成・上書きされた場合だけ MCP の状態を再検出する。
- 依存関係準備時に `pnpm fetch --frozen-lockfile` を試したが、環境から npm registry への DNS 解決ができず完了しなかった。Node.js の TypeScript strip-types 実行で CLI の再現確認は実施できた。

## 完了まとめ

- `initConfig` が `created | skipped | overwritten` を返すようにし、MCP `init` の既存設定スキップ時に警告を返すようにした。
- CLI/MCP の README、CLI リファレンス、クイックスタート、ユーザーガイドに生成先と非上書き動作を追記した。
- CLI unit 9件、MCP unit 23件、TypeScript build、対象実装の ESLint、`git diff --check` が成功した。
- MCP ライフサイクル E2E は、embedding global setup がローカル ONNX モデル未配置で起動できず、テストコードの実行前に停止した。
- Issue コメント: https://github.com/otolab/search-docs/issues/122#issuecomment-5536173290
