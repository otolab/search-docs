# Issue #151: writer heartbeat のタイムゾーン

## 作業計画

- 実 LanceDB の timestamp 型と既存データの読み取り、claim・takeover 経路を確認する。
- 経過時間を UTC 基準で算出し、実 DB と異なるタイムゾーンのプロセスで回帰検証する。
- 結果と制約を Issue に記録し、テストと PR を作成する。

## 結果

- 通常の overwrite 後は `timestamp[us, tz=UTC]`、初期スキーマは `timestamp[ms]`（timezone なし）。導入時から writer は UTC で記録している。
- UTC 基準で差分を算出し、timezone なしの値は UTC として解釈する。
- 実 DB の別プロセスによるタイムゾーン別テストと、WatcherProcess の定期確認から takeover までの統合テストを追加した。期限切れデータは過去時刻を投入して作成し、実時間の 120 秒待機はしていない。
- #150 の旧 writer 復帰時の競合は対象外。

## CI 失敗への対応

- unit test 環境に `uv` がないため実 DB 統合テストが失敗した。統合テストを独立させ、unit test と個別の統合テストを再検証する。
- server の unit test 110 件と独立した heartbeat 統合テスト 1 件が成功。unit test はサンドボックス内で FSEvents が起動できず、権限制限のない環境で再実行した。現行 CI は統合テストを実行しない。
