# Issue 139: Embedding model prefetch and startup timeout

**Status**: Draft PR #140; reviewer cleanup fixes and changeset added
**Issue**: https://github.com/otolab/search-docs/issues/139

## Approach

- Use `SEARCH_DOCS_EMBEDDING_READY_TIMEOUT_MS` with a 10-minute default and `--ready-timeout <ms>` on `embedding start` and `server start`.
- Use the same readiness budget in the CLI embedding lifecycle and server's local embedding startup. Give `server start` an additional bounded startup grace so its daemon health wait cannot expire first.
- Add `embedding download [--runtime onnx|torch] [--model <repo>]`, using `huggingface_hub.snapshot_download` and its normal Hugging Face cache. Default each runtime to its existing Ruri model.
- Document first-run download expectations and prefetch usage; test timeout parsing/propagation and both CLI/Python download paths without requiring live Hugging Face access.

## Design note

The Issue reproduces the default ONNX model path. The download command will support both existing runtimes, with runtime-specific defaults, to preserve the existing CLI's runtime choice. The timeout option and environment variable use milliseconds; the initial default is 600,000 ms.
