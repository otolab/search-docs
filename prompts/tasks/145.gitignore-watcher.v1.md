# Issue #145: 監視時の .gitignore 判定

## 作業計画

- 初期同期と監視の判定を共通化し、監視開始時のルート `.gitignore` を利用する。
- 設定の有効・無効、追加・変更、監視再開始時の反映を実ファイルで検証する。
- 利用者向け文書に反映タイミングと既存索引への影響を記載する。

## 完了メモ

- 監視開始時に `.gitignore` を読み込み、初期同期と同じ判定を使用する。再開始時には削除された `.gitignore` も反映する。
- 実ファイルの追加・更新、設定の両値、監視再開始を含む対象テスト20件が成功。
- `pnpm exec tsc --build packages/server --force` が成功。パッケージの build は環境の TypeScript 6.0.3 を拾い、既存設定の非推奨エラーで失敗した。

## レビュー対応計画

- 削除イベントは `.gitignore` だけを迂回し、sources と exclude の判定は維持する。
- 実ファイルの監視、索引・ストレージへの登録、除外設定後の監視再開と削除を通して確認する。
- `.gitignore` の変更だけでは削除せず、実ファイル削除時に後片付けすることを文書に補足する。

## レビュー対応結果

- `unlink` は `.gitignore` を迂回し、従来の sources・exclude の制約を維持する。
- 実 DB・埋め込みサーバー・FileStorage を使用し、監視による索引作成から除外設定、再開、実ファイル削除までを確認した。対象21テストと TypeScript 5.9.3 のビルドが成功。
