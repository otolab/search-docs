# Issue #30: セクション番号表示の修正作業計画

## 問題の整理

### 現状の問題
修正後のコード（コミット 9909948）では：
- document root (depth=0): `sectionNumber=[1]`
- H1 (depth=1): `sectionNumber=[1]`

**同じsectionNumberになり、区別できない問題が発生**

### 例
```markdown
text

# title

abc

## section
```

この場合、前文"text"を含むdocument rootと、H1 "title"の区別ができない。

### 正しい仕様
document rootのsectionNumberを空配列`[]`にする：

- document root (depth=0): `sectionNumber=[]`
- H1 (depth=1): `sectionNumber=[1]`
- H2 (depth=2): `sectionNumber=[1, 1]`
- H3 (depth=3): `sectionNumber=[1, 1, 1]`

これにより：
- document rootは特別な存在として階層番号を持たない
- H1から自然な番号付けが始まる（1, 2, 3...）
- get_outlineでの表示も「1: Level 1」となり直感的

## 影響範囲の分析

### 1. データ層（変更なし）
- DBのスキーマ: 変更不要（sectionNumberは配列型で空配列も許容）
- 既存データ: 再インデックスが必要だが、スキーマ変更は不要

### 2. ビジネスロジック層
#### 2.1 セクション生成（markdown-splitter.ts）
- `buildSections()`: document rootのsectionNumberを`[]`に変更

#### 2.2 API層（search-docs-server.ts）
- `getOutline()`: depth=0のフィルタリング処理を維持（sectionNumber判定は不要）

### 3. 表示・UI層（MCPツール）
#### 3.1 検索結果表示（search.ts）
- `formatSectionNumber()`: 空配列の処理を追加
  - `[]` → "(文書全体)" または表示しない

#### 3.2 ドキュメント表示（get-document.ts）
- `sectionNumber.join('-')`: 空配列の処理を追加
  - `[]` → "(root)" または "0"

#### 3.3 アウトライン表示（get-outline.ts）
- 影響なし（depth=0は既にフィルタリングされている）

### 4. テスト
- `get-outline.test.ts`: sectionNumberを`[]`に更新
- `markdown-splitter.test.ts`: 既存テストの確認
