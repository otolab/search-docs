# Issue #144: Embedding provider

## 作業計画

1. 現行の起動・設定・CLI・Python worker の経路と既存の互換性を調査する。
2. provider ごとの責務と設定を整理し、既存設定の振る舞いを維持しながら OpenAI 互換を追加する。
3. HTTP 応答、次元、秘密情報、起動と index / search を検証する。
4. CLI と利用者向け・開発者向け文書を更新し、結果を Issue に記録する。

## 調査メモ

従来の設定ファイル `embeddingUrl` は接続失敗時に自動検出へ fallback する一方、環境変数 `EMBEDDING_URL` は厳格な接続指定である。明示的な外部 provider と区別して維持する必要がある。

## 中断時点

設定・provider の起動・Python 通信に着手したが、依存関係がなく検証できていない。`pnpm install --frozen-lockfile --offline` は必要なパッケージが store にないため失敗。CLI、文書、テストおよび拡張構造の仕上げは未完了。途中の変更は完成品として扱わない。

## 実装・検証（PR 作成前）

Node 依存は `pnpm install --frozen-lockfile`、Python は db-engine の `pyproject.toml` を使った仮想環境で導入した。lockfile は変更していない。設定から HTTP mock、Python worker、索引追加・検索までの経路と、モデル変更による identity 不一致を確認した。既存 Ollama の統合テスト、provider の応答検証、CLI と既存 fallback の対象テスト、ビルド・lint・シェル構文チェックを実行した。

懸念: OpenAI 互換の索引 identity は provider・モデル・次元を記録するが、接続先 URL は含めていない。同じモデル名で別のベクトル空間を返す別ホストに切り替えた場合は自動検出できない。実際の外部サービスへの接続は未検証。
