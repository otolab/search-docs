# README.mdリファクタリング作業メモ

**Issue**: #38 - ドキュメント構造の整理と使い方説明の改善
**作業日**: 2026-01-15
**担当**: Claude Code

## 作業の目的

現在のREADME.mdは機能説明やインストール手順が中心で、以下の問題がある：
- プロジェクトのコンセプトが伝わりにくい
- 取っ掛かりが簡単に見えない（claude mcp addが目立たない）
- システムの本質的な仕組みの説明が不足
- 詳細な情報が多すぎて初見で圧倒される

**目的**: README.mdを「プロジェクトの顔」として機能させる
- 5秒でコンセプトが理解できる
- 30秒で試せることがわかる
- 1分でシステムの本質が理解できる
- 次のステップ（詳細ドキュメント）への導線が明確

## 新しい構成方針

### 1. コンセプト優先（What + Why）
- search-docsとは何か
- なぜ必要か（解決する課題）
- 核となる価値提案

### 2. 取っ掛かりの簡単さ
- `claude mcp add npx -- -y @search-docs/mcp-server` を目立たせる
- 30秒で始められることを強調
- その他の使い方は後回し

### 3. システムの本質（How）
- シンプルな3層構造の図解
- Document → Section → Vector Index → AIエージェント
- 詳細はarchitecture.mdへ誘導

### 4. 主な特徴（簡潔に）
- セクション分割検索
- リアルタイム更新
- プロジェクト独立
- 日本語最適化

### 5. ドキュメント誘導
- 目的別に整理
- 使い始める / 詳しく知る / 統合する

## 削除する内容（他へ移動）

- 技術スタックの詳細 → architecture.md
